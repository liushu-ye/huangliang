# 黄粱一梦（huangliang）

一个「每次打开 App 单独计时、到点打断你」的 Android 小工具。

不是统计你今天用了多久，而是在你每一次沉浸进去的时候提醒你 —— 抖音刷到第 15 分钟该停了。

## 功能

- 从手机已安装应用里挑选要监控的 App（含常见娱乐 App 快捷添加）
- 为每个 App 单独设置单次使用时长，之后可以随时编辑调整，改完立即生效
- 每次进入目标 App 重新计时，离开即结束本次会话
- 到点后弹出**悬浮窗提醒**，盖在目标 App 上面，必须手动处理
- 点「好，我退出」后，通过无障碍服务**直接把你送回桌面**
- 如果说了要退却没退，一段时间后会追问「你怎么还没退出」
- 提醒支持「再玩 5 分钟」顺延
- 主页和提醒弹窗会随机显示一句关于时间的标语
- 息屏自动结束会话，不会在锁屏时偷偷计时
- 后台前台服务常驻监控，进程被杀或重启后自动恢复
- 配置保存在本地，不上传任何数据

## 权限

App 依赖下面几个系统权限，首次打开时界面会逐条引导：

| 权限 | 用途 | 是否必须 |
| --- | --- | --- |
| **使用情况访问权限** | 判断当前前台是哪个 App | 必须，否则无法计时 |
| **悬浮窗权限** | 到点后盖一个大提醒框 | 建议，不开启则只发通知 |
| **通知权限**（Android 13+） | 显示提醒和后台常驻通知 | 建议 |
| **无障碍服务** | 「好，我退出」直接回桌面 | 可选，不开启则只能手动退 |

无障碍服务只调用 `GLOBAL_ACTION_HOME` 这一个全局动作，`canRetrieveWindowContent=false`，
**不会读取任何屏幕内容**。

## 编译

需要 JDK 17+ 和 Android SDK（compileSdk 35）。

```bash
./gradlew assembleDebug
```

产物在 `app/build/outputs/apk/debug/app-debug.apk`。

> 注意：项目放在含中文的路径下时会被 AGP 拒绝构建。`gradle.properties` 里已经加了
> `android.overridePathCheck=true` 绕开这个检查，但更推荐把项目放在纯英文路径下。

## 实现要点

几个踩过的坑，记下来免得重蹈覆辙：

- **前台 App 判定**：`UsageStatsManager.queryEvents` 的查询窗口必须从「上次检查的时间点」往后推进。
  如果每次都只查最近几秒，目标 App 打开超过几秒后就再也查不到事件，会话计时会被反复中断，
  提醒永远触发不了。
- **软件包可见性**：Android 11+ 不声明 `QUERY_ALL_PACKAGES` 的话，`getInstalledApplications`
  只能看到系统应用，选择器里会空得只剩设置、电话这类系统 App。
- **前台服务类型**：targetSdk 34+ 必须在 `startForeground` 时给出已声明的前台服务类型，
  否则抛 `MissingForegroundServiceTypeException` 直接崩溃。
- **API 版本分支**：`AppOpsManager.unsafeCheckOpNoThrow` 是 API 29 才有的，
  minSdk 26 的机型上必须回退到 `checkOpNoThrow`。
- **关不掉别的 App**：Android 没有「结束其他 App 进程」的公开 API，
  `killBackgroundProcesses` 对前台应用无效。能做到的是用无障碍服务
  `GLOBAL_ACTION_HOME` 把用户送回桌面 —— 这也是「好，我退出」的实现方式，
  做不到就退而求其次，超时追问。

## 已知限制

- 部分厂商 ROM 会拦截开机自启和后台前台服务，需要在系统设置里手动放行
  （电池优化白名单 / 自启动管理），否则监控可能被系统悄悄干掉
- 判定依据是使用事件，切到系统桌面以外的浮层（比如下拉通知栏）时仍算作在使用中
- 无障碍服务是「送回桌面」而不是「杀掉进程」，目标 App 仍在后台存活
